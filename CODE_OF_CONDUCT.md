# OpenVisionBridge Code of Conduct

## 1. Purpose

OpenVisionBridge is a technical community project for visual perception, structured visual representation, AI reasoning, and related engineering.

This Code of Conduct applies to project repositories, issues, pull requests, discussions, documentation, community channels, and other official project spaces.

## 2. Expected Behavior

Participants should:

- communicate respectfully;
- focus criticism on ideas, evidence, implementations, or decisions;
- assume good faith unless evidence indicates otherwise;
- provide constructive feedback;
- welcome different levels of experience;
- respect contributor rights and licenses;
- protect private information;
- report security issues responsibly;
- acknowledge uncertainty in technical claims.

## 3. Technical Disagreement

Strong disagreement about architecture, algorithms, models, benchmarks, dependencies, performance, APIs, or schemas is acceptable.

Critique the technical claim, not the person.

Preferred:

> This implementation duplicates the image three times and increases memory use.

Not preferred:

> Anyone proposing this does not understand computer vision.

## 4. Unacceptable Behavior

The project does not accept:

- harassment;
- threats;
- intimidation;
- personal attacks;
- discriminatory conduct;
- targeted insults;
- sexual harassment;
- doxxing;
- unauthorized publication of private information;
- malicious disruption;
- deliberate impersonation;
- repeated bad-faith conduct;
- deliberate technical misinformation;
- unauthorized disclosure of security vulnerabilities;
- attempts to bypass project licensing requirements;
- knowingly infringing submissions.

## 5. Intellectual Property

Respect copyright, software licenses, model licenses, datasets, trademarks, privacy rights, and contributor rights.

Do not submit material you do not have the right to contribute.

## 6. Security

Security vulnerabilities should be reported according to `SECURITY.md`, rather than publicly exposing exploitable details.

## 7. Maintainer Responsibilities

Maintainers should apply project rules consistently, respond to legitimate concerns, protect contributor privacy where practical, document significant governance decisions, and address serious violations.

## 8. Enforcement

Depending on severity and circumstances, maintainers may:

1. provide informal guidance;
2. request corrective behavior;
3. moderate discussion;
4. remove inappropriate content;
5. temporarily restrict participation;
6. suspend contribution privileges;
7. permanently exclude a participant from project spaces.

## 9. Reports

Reports should be made in good faith. Knowingly fabricated allegations or abuse of the reporting process may itself violate this Code.

A good-faith report that cannot be substantiated is not itself misconduct.

The repository should publish the current reporting contact separately.

## 10. Privacy

Information provided during a conduct report should be handled as privately as reasonably practical and disclosed only when necessary for investigation, protection, legal compliance, or security/safety response.

## 11. Final Principle

```text
Challenge the idea.
Examine the evidence.
Improve the implementation.
Respect the person.
```
